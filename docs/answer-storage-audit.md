# ตรวจการเก็บคำตอบใน Sim — 2 กันยายน 2569

คำตอบ K/P/V บันทึกซ้ำเป็นแถวรายบุคคลใน student_responses โดยอ้างอิงรหัสสมาชิกที่คงที่
การเปลี่ยนคำตอบบันทึกใน learning_events พร้อมคำตอบก่อนหน้า คำตอบใหม่ รหัสเหตุการณ์ และเวลาที่ตอบ
ค่าปัจจุบันใน save_state กับประวัติการเปลี่ยนคำตอบจึงแยกกัน ไม่เก็บเฉพาะคำตอบสุดท้าย

หน้าดูวัสดุ/ซูม การหมุนกล่อง ปุ่มเลือกคำในคลังก่อนนำไปจับคู่ และการนำทาง ไม่ใช่คำตอบที่ส่ง
ห้องดูดซับน้ำไม่มีช่องคำตอบอิสระ ผลในหน้านี้เป็นค่าจากแบบจำลองที่เด็กกดบันทึก
โหมดทดลองอิสระที่ไม่มีทีมยังเป็น preview ในเครื่อง ไม่บันทึกปะปนกับข้อมูลนักเรียน
ภารกิจ 3–5 ที่ยังล็อกไม่ได้มีแบบตอบใหม่เพิ่มในงานนี้

## การแสดงผล

- หน้าเลือก/จัดการทีมมีจำนวนร่องรอยที่ตอบ และปุ่ม “ดูคำตอบ” ใช้ได้ทั้งรอบกำลังทำและรอบที่จบแล้ว
- หน้าดูคำตอบแสดงร่องรอยกล่อง → สาเหตุที่เด็กเลือก หัวข้อที่ศึกษา คำตอบ K/P/V และประวัติตัวเลือกแบบทบทวน
- Dashboard ครูมีหัวข้อคำตอบจากหน้าหมุนกล่องและแบบทบทวนด้วย
- ป้าย “บันทึกในฐานข้อมูลแล้ว” แสดงเมื่อเซิร์ฟเวอร์ตอบรับสำเร็จ ส่วน “ยืนยันแล้ว” หมายถึงนักเรียนยืนยันคำตอบ ไม่ใช่สถานะเครือข่าย

## ความทนทานและข้อจำกัด

- เขียนคิวในเครื่องทันที ก่อนหน่วงการส่งเครือข่าย 350 มิลลิวินาที
- ส่งทีละชุด ปรับ revision หลังเซิร์ฟเวอร์ตอบรับ ไม่ล้างคำตอบใหม่ที่เข้าระหว่างส่ง
- รวม snapshot ต่อรอบแต่รักษาประวัติการตอบทั้งหมด ไม่ตัดคิวทิ้งเมื่อเกิน 20 รายการ
- ส่งซ้ำเมื่อออนไลน์และทุก 10 วินาที เก็บคิวข้ามการรีโหลดเมื่อพื้นที่เก็บข้อมูลเบราว์เซอร์ใช้ได้
- ตรวจ checkpointId เพื่อรู้ว่าคำขอที่ขาดการตอบกลับถูกบันทึกไปแล้วหรือไม่
- ถ้ามีอีกเครื่องแก้รอบเดียวกัน จะเตือนข้อมูลชนและเก็บคำตอบรอไว้ ไม่เขียนทับคำตอบของอีกเครื่องอัตโนมัติ
- หากพื้นที่เก็บข้อมูลเบราว์เซอร์เต็ม เก็บในหน่วยความจำและพยายามส่ง แต่ไม่รับประกันการอยู่รอดข้ามปิดแท็บจนกว่าจะส่งสำเร็จ
- ไม่สามารถกู้คำตอบในอดีตที่ระบบเก่าไม่เคยส่งหรือเก็บไว้ได้

## การตรวจสอบ

- TypeScript ผ่าน: pnpm run lint
- Unit/contract tests ผ่าน 68 ข้อ; live test แยกไว้และไม่ทำงานในการทดสอบปกติ
- ทดสอบฐานข้อมูลจริงด้วยทีมสังเคราะห์ชื่อขึ้นต้น “QA คำตอบ”: ตรวจ game_runs, student_responses, learning_events และอ่านรอบกลับมา
- ทดสอบหน้า Sim จริง: แสดงร่องรอยทั้ง 4 จุดบนหน้าดูคำตอบ และแก้เหตุผล V โดยไม่กดยืนยัน ตรวจพบข้อความเดียวกันทั้ง game_runs และ student_responses
- รีโหลดแล้วเปิดทีมเดิม อ่านคำตอบจากฐานข้อมูลได้ ไม่อาศัยการกรอกใหม่
- ไม่ได้ทดสอบหน้า Dashboard ที่ต้องล็อกอินครูผ่าน UI; ตรวจโค้ดและ TypeScript ของหน้านั้นแล้ว
- เหลือทีม QA สังเคราะห์ 1 ทีมสำหรับแยกตรวจ ไม่แก้คำตอบของทีมผู้เรียนเดิม

การทดสอบจริงในอนาคต: ตั้ง RUN_LIVE_ANSWER_TEST=1 และรัน answers.live.test.ts
ใช้ LIVE_QA_TEAM_NAME เพื่อใช้ทีม QA เดิม มิฉะนั้นการรันจะสร้างทีม QA ใหม่หนึ่งทีม
